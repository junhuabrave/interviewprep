# Dynamic Programming

## How to recognize a DP problem

- "Count the number of ways..."
- "Find the min/max cost / longest / shortest..."
- "Can you reach...?"
- Decisions made one step at a time, where the choice depends on previous choices.

If a brute-force recursion has overlapping subproblems, DP applies.

## The 4-step recipe

1. **Define the state.** What parameters fully describe a subproblem? `dp[i]`, `dp[i][j]`, `dp[i][k]`...
2. **Write the recurrence.** Express `dp[state]` in terms of smaller states.
3. **Pick base cases.**
4. **Choose direction.** Top-down (recursion + memo) or bottom-up (iterative table).

## Common patterns

### 1D linear DP
- **Climbing Stairs**: `dp[i] = dp[i-1] + dp[i-2]`.
- **House Robber**: `dp[i] = max(dp[i-1], dp[i-2] + nums[i])`.
- **Decode Ways**: similar — track ways to reach position i.

### Unbounded knapsack / coin change
- **Coin Change** (min coins to make amount):
  ```
  dp[0] = 0; dp[a] = min(dp[a-c] + 1 for c in coins)
  ```
- **Coin Change 2** (count combos): outer loop coins, inner loop amounts → avoids counting permutations.

### 0/1 knapsack
- **Items 1..n, capacity W**: `dp[i][w] = max(dp[i-1][w], dp[i-1][w-wt[i]] + val[i])`.
- Space-optimize to 1D: iterate `w` from `W` down to `wt[i]` (so old values aren't overwritten).

### Subsequence DP
- **LIS (Longest Increasing Subsequence)**:
  - O(n²): `dp[i] = 1 + max(dp[j] for j<i if a[j]<a[i])`.
  - O(n log n): patience-sorting; maintain `tails[]` and binary-search insert.
- **LCS (Longest Common Subsequence)**:
  ```
  dp[i][j] = dp[i-1][j-1] + 1            if s[i-1] == t[j-1]
           = max(dp[i-1][j], dp[i][j-1]) otherwise
  ```
- **Edit Distance** (Levenshtein):
  ```
  dp[i][j] = dp[i-1][j-1]  if equal
           = 1 + min(dp[i-1][j], dp[i][j-1], dp[i-1][j-1])  otherwise
  ```

### Interval DP
- **Burst Balloons**, **Matrix Chain Multiplication**:
  ```
  for length in 2..n:
      for i in 0..n-length:
          j = i + length - 1
          for k in i..j:
              dp[i][j] = best of dp[i][k] + dp[k+1][j] + cost(...)
  ```

### State-machine DP
- **Best Time to Buy/Sell Stock** with cooldown / fee / k transactions.
- Define states: `held` (holding stock), `sold` (just sold), `rest` (idle). Transition between states.

### Partition / palindrome DP
- **Palindrome Partitioning II**: combine LPS table with cut DP.
- **Word Break**: `dp[i] = any(dp[j] and s[j:i] in dict)`.

### Tree DP
- "Best answer rooted at this node" — combine children, decide include/exclude this node.
- Examples: House Robber III, Binary Tree Cameras.

### Bitmask DP
- For n ≤ 20: state = subset bitmask.
- **Traveling Salesman**: `dp[mask][last]` = min cost to visit set `mask` ending at `last`.

## Top-down vs bottom-up

- **Top-down (memoization)**: easier to write, mirrors recurrence. Uses recursion stack.
- **Bottom-up**: avoids stack, often faster, allows space optimization. Order matters — fill in dependency order.

## Common gotchas

- **Off-by-one in dimensions**: `dp[n+1][m+1]` is common; index arithmetic shifts.
- **Wrong iteration order in 0/1 knapsack** (forwards) → counts each item multiple times.
- **Initializing wrong**: `0` vs `-inf` vs `inf` matters depending on min/max/count.
- **Missing base cases** for empty input or boundary.
- **Forgetting that LIS strictly < vs ≤** changes the answer.
